# 需要から何機・何基要るか — 計算の結果

需要から、要る機体とエンジンの数を出す計算の結果をまとめる。会社全体を座席キロで見る層（`fleet_from_demand.py`）と、幹線を空港の枠と機種ごとの割当で見る層（`airport_slots.py`・`route_fleet.py`）の二段。基準月は 2026-10（t=0）、24 か月、為替 157 円/$。下では二つの会社を「会社 A」「会社 B」と呼ぶ（設定は `data/companies.json`）。

数値は合成データと公開値の混合。出典のない前提は JSON の中で `no_source` と書いてある。

## 1. 出るもの

`fleet/<会社>.json` に次の順で入る。

- `demand_rpk_737`：月ごとの需要の帯（p10／p50／p90）。
- `aircraft`：要る機数、点検で止まる機、余り、p90 で足りない月、全機が飛んだときの搭乗率。
- `engines`：飛ぶ機 × 2 ＋ 予備 ＋ 短期リース、保有との余力。
- `levers`：足りない月の打ち手と費用、余る月の維持費。
- `planning_season`：年度の始まりに固める数字。
- `long_view`：20 年の退役後の機数と需要。
- `consistency`：737 の需要の割合（仮定）が機材と整合するか。
- `trunk`：幹線の層。空港の枠、機種 × 1 日の飛び方の割当、地方路線、エンジン、借りるかどうか、再配分シナリオ。

## 2. 会社全体（座席キロで数える）

| | 会社 A（737 56 機） | 会社 B（737 39 機） |
|---|---|---|
| FY2027 要る機数 p50 最大／p90 最大 | 50.1／53.8 | 44.9／48.1 |
| p90 で足りない月 | FY2028 の 8 月だけ（0.3 機） | FY2027 は 11 か月 |
| 逼迫月（8 月）に全機が飛ぶときの搭乗率 | 0.76 | 0.98 |
| 逼迫月のエンジン余力（p90） | 13 基 | 5 基 |
| 平年の整備費 | 266.8 億円/年 | 150.0 億円/年 |
| 需要の伸び（年 3.8%）による増分 | +10.1 億円/年 | +5.7 億円/年 |
| 737 の需要の割合と機材 | 整合 | 不整合（整合する割合は 0.234） |

会社 B の「足りない月」は、需要が多いからではない。737 が運ぶ需要の割合（0.28、仮定）が 39 機に対して大きすぎ、全機が飛んでも搭乗率 98〜102% が要る月が出るため。会社 B を使うなら、この割合を先に直す。

## 3. 幹線（空港の枠の中で、機種ごとに割り当てる）

羽田の国内線の発着枠（1 日 465 枠）の会社別配分から、幹線 4 路線（羽田–新千歳・伊丹・福岡・那覇）に使える往復便数を出す（会社 A 61、会社 B 64）。路線全体の旅客（2024 年の公開値）を 2026-10 まで伸ばし、他社との便数の比率で自社分を出す。その需要を、機種 × 1 日の飛び方（羽田発着のパターン）の割当として月ごとに解く。

会社 A の FY2027（p50）：

| | 値 |
|---|---|
| 年次の版の機数 | 737 6・787 3・A350 15 |
| 年次の版の往復便数 | 新千歳 16・伊丹 16・福岡 17・那覇 12・福岡–那覇 6 |
| 737 が幹線で運ぶ割合（737 の人キロ） | 16% |
| 8 月に乗れない旅客／失う売上 | 9.25 万人／8.05 億円（大半は伊丹） |
| 年度で失う売上 | 15.2 億円 |
| 737 を借りる機・月 | 0（借りても入れる枠がない） |
| 737 の 1 日の飛行回数（幹線／会社全体／ふだん） | 5.75／5.44／5.38 |
| 737 の稼働倍率／入場の前倒し | 1.011／6 基（平均 −1.0 か月） |
| 737 の平年の整備費 | 263.0 億円/年 |

縛りは機体の数ではなく羽田の枠。繁忙月は A350 を上限まで使い、737 は余る。区間が短く 1 人あたりの売上が小さい伊丹から便を削り、長い区間に回す解になる。

## 4. 2028 年の発着枠の再配分シナリオ（会社 A、FY2027、p50）

幹線の枠を ±n 往復動かして解き直す。変化はすべて幹線に寄せ、他社の便数は据え置く。

| 幹線の枠 | 旅客（千人） | 売上（億円） | 運航費（億円） | 差し引きの変化（億円） | 737 の稼働倍率 |
|---|---|---|---|---|---|
| −9 | 10,993 | 1,692 | 609 | −112.6 | 1.010 |
| −5 | 11,595 | 1,765 | 640 | −70.1 | 1.015 |
| −3 | 11,941 | 1,827 | 664 | −32.5 | 1.014 |
| 0 | 12,354 | 1,879 | 683 | 0 | 1.011 |
| +3 | 12,626 | 1,915 | 700 | +19.6 | 1.009 |
| +5 | 12,973 | 1,989 | 726 | +68.0 | 1.012 |

枠を失う側は 1 往復あたり年に 11〜14 億円、得る側は増えた往復をどの路線に足すかで 7〜14 億円になる。737 の飛び方とエンジンの入場はほとんど動かないので、再配分は売上の問題になる。

借りる解が出るのは、幹線に回せる 737 が 4 機ほどまで減り、便を欠航させるしかないときだけ。そのとき借りる理由は売上ではなく、枠を使い続けること（使わない枠は回収の対象）。欠航には 1 往復・1 か月あたり 5,000 k$ の罰金を置いている（再配分シナリオの 1 往復の年の価値の 1 か月分に近い、仮定）。

## 5. 前提と出典

- **原典で照合した公開値。** 路線ごとの旅客と座席利用率（国交省 2025-03-19）、羽田の枠の配分と 2023-03 の便数・地方枠・1 便／3 便ルール（国交省 2024-03-14）。URL はデータファイルに書いてある。
- **原典を確認していない値。** 2026 年の便数、機種ごとの機数。データには「未確認」と書いてある。
- **仮定（no_source）。** 737 が運ぶ需要の割合、目標搭乗率、運賃単価 15 円/人キロ、リース料、需要の帯の幅、機種ごとの運航費・折り返し時間・幹線に回せる上限、季節の偏り、パターン。
- **見送りの売上は下限。** 乗り継ぎや次の便への振り替えを含めていない。
- **欠けている月の補い方。** 会社の実績が欠けている月は、市場の季節指数 × 会社の割合で補っている。

## 6. 限界

- 割当は安い席を選ぶので、月平均の搭乗率が上限 0.88 に張り付く（実績は 75〜83%）。1 便の平均席数も実績からの推計より大きい。
- 会社 A の 767 はほとんど使われない（A350 のほうが 1 席あたり安い）。
- A350・777 などはエンジン計画のデータがないので、飛行回数だけを出す。
- 機種が多い会社 B は、幹線の層の計算に約 13 分かかる。

## 7. 実行

```bash
python3 fleet_from_demand.py jal --out fleet/jal.json      # 会社 B は ana
python3 export_trunk_assignment.py jal --label "Company A" --out trunk_assignment.json
python3 -m unittest tests.test_fleet_from_demand tests.test_route_fleet
```

`run_all.sh` は growth の後に `fleet_from_demand.py` を呼び、結果を `fleet/` に写す。
