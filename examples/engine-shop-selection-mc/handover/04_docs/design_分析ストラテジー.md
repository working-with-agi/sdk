# 概念設計：分析ストラテジーを選べるようにする

## 一言で

**ストラテジー＝「新しい情報をどう重みづけるか」の設定を、名前つきで一束にしたもの。** 計算の中身は変えず、4 つのつまみだけを束ねて差し替える。

## ストラテジー（4 つ）

| 名前 | 考え方 | つまみの値 |
|---|---|---|
| 平均（既定） | 全期間を等しく見る。レジームは一つ | 忘却なし、K 大きめ、変化点で切らない、伸びは長期 |
| 新しさ優先 | 直近を重く、古い月を薄める | 忘却の半減期 6〜12 か月、K 小さめ、伸びは直近 |
| クラスタ | 段が変わったら切り替える | 変化点で n をリセット、世界を足す、古い世界に下限 |
| 混成（推奨） | 平均を既定に、ゆっくり忘れ、検知で切る | 半減期 12 か月、K 中、変化点で切る、伸びは地平で混ぜる |

## つまみ（4 つ）と差し込み口（3 か所）

| つまみ | 何を決めるか | 差し込み口 |
|---|---|---|
| 忘却 λ（半減期） | 世界の確率で、古い月をどれだけ薄めるか | 追跡（`track.py`） |
| K（事前の重さ） | 実績 n 件で前提をどれだけ動かすか n/(n+K) | 次の版への学習（`roll.py`） |
| 変化点で切るか | 検知後に古い実績を捨てる／世界を足す／古い世界の下限 | 追跡・学習（`cpd.py` の結果を使う） |
| 伸びの混ぜ方 | 直近か長期か、地平でどう混ぜるか | 需要の前提（`plan_from_demand.py`） |

ストラテジーは `data/strategies.json` に置く。各モジュールは `--strategy <名前>` で受け取り、つまみを読むだけ。

## 選び方（人が選ぶ・採点が助ける）

```
ストラテジー 4 つ ──→ 過去で検証（学ぶ 5 版／確かめる 5 版）──→ 採点表 ──→ 人が 1 つ選ぶ ──→ 年次の版で使う
                                                               （被覆率・入場時期のずれ・需要の誤差）
```

- 採点は年 1 回（バックテスト）。表で見て人が選ぶ。自動では切り替えない。
- 選んだ名前は版に記録され、レポートの表紙と「前提と出典」に出る。
- 月次では変えない。変えるのは年次の版か、変化点が出て「クラスタ」に切り替える判断をしたとき。

## 画面

- 対話版レポート「過去で検証」に **採点表（4 行）** と、今の版が使うストラテジーの印。
- A4 版 付録 B の末尾に同じ表。
- ダッシュボードの見出しに「ストラテジー：混成」。

## やらないこと

- つまみを個別に細かく動かす UI は作らない（4 つの名前から選ぶだけ）。
- 自動で最良を選ぶ仕組みは入れない（採点はするが、選ぶのは人）。
