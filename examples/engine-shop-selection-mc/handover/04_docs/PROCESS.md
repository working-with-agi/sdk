# 業務プロセスに合わせた作り（設計案）

エンジン管理の業務を、周期と担当と「どこで何を決めるか」で並べ、道具（最適化・追跡・画面）をその流れの中に置き直すための設計です。業務の中身は公開情報（`PRACTICE.md`）と各社の採用ページの記述から組み立てた一般形で、個社の実際の手順ではありません。

## 1. 業務プロセスの全体

| # | プロセス | 周期 | 主な担当（各社の呼び方は異なる） | 決めること | 今の道具 |
|---|---|---|---|---|---|
| P1 | 長期計画と年間予算 | 年 1 回（＋半期見直し） | エンジン計画、財務、経営 | 年間の取卸し計画、整備費予算、予備エンジン方針、機材更新との整合 | 基準の計画、10 年の見通し、季節の平年値 |
| P2 | 工場との年間入場計画の合意 | 年 1 回・四半期 | エンジン計画、調達 | 契約工場への入場枠、寿命部品キットの発注計画 | 一部（枠と判断期限） |
| P3 | 月次の計画会議 | 毎月 | エンジン計画、技術、運用 | 入場の確定・前倒し・据え置き、予備の配置、前提が外れたときの乗り換え | 月次計画、追跡 |
| P4 | 取卸し判断 | 随時（監視は毎日） | パワープラント技術 | 警報やボアスコープ所見への処置、取卸すか様子を見るか、エンジン交換の段取り | なし |
| P5 | 入場から出場まで（1 回ごと） | 入場ごと（4〜6 か月） | エンジン計画、技術、工場 | 整備範囲の依頼、見積もりの承認、追加作業、部品待ちの対応、受領 | なし |
| P6 | 予定外の事態 | 随時 | 運用、エンジン計画 | 予備不足の埋め方（リース、プール、代替機材、欠航）、鳥の衝突などの修理範囲と保険 | 一部（モデルの中の埋め方） |
| P7 | 信頼性管理 | 毎月・四半期 | 信頼性管理、技術、委員会 | 警戒値の超過の調査、是正処置、整備プログラムの変更、当局報告 | なし |
| P8 | 技術管理 | 随時 | 技術 | 耐空性改善通報・技術通報の評価（期限あり）、改修をどの入場で入れるか | なし |
| P9 | 契約・調達 | 四半期・契約更新時 | 調達、エンジン計画 | 工場の成績評価、契約更新の入札、寿命部品・中古部品の調達、保証請求 | 5 工場の比較（入札） |
| P10 | 財務・会計 | 毎月・決算 | 財務 | 予実、請求の照合、積立・引当、リース返却の精算 | 一部（年度の着地見込み） |
| P11 | 予定にない打診・交渉 | 随時 | エンジン計画、調達、経営 | エンジン売買・リース、工場からの提案を受けるか、上限価格 | 一部（打ち手の効果） |

## 2. プロセスのつながり

```
P1 年間計画・予算 ──▶ P2 工場と入場枠 ──▶ P3 月次会議 ──▶ P5 入場〜出場 ──▶ P10 請求・予実
       ▲                                 ▲   │               │
       │                                 │   ▼               ▼
  P7 信頼性管理 ◀── P4 取卸し判断 ◀── 状態監視        P9 工場の成績・契約更新
       │                                 ▲
       └──────── P8 技術管理（改修） ─────┘      P6 予定外・P11 打診はどこからでも割り込む
```

- 実績は P5・P4・P6 で生まれ、P3（追跡）・P7（信頼性）・P10（予実）に集まり、次の P1（版の積み上がり）に返る。
- 判断には期限がある（工場の枠予約、キット発注、通報の評価期限、打診の回答期限）。期限は P3 で一覧にする。

## 3. 作りの原則

1. **業務の対象を記録として持つ**：エンジン、取卸し、入場（工場整備 1 回）、見積もり、判断、承認、計画の版。画面はその記録の見方の一つにする。
2. **入場は状態を持つ**：計画 → 枠予約 → 取卸し → 輸送 → 受入・分解 → 見積もり提示 → 承認 → 修理（部品待ち）→ 組立・試運転 → 出場 → 受領 → 請求照合 → 完了。どの状態に何日いるかが、工期の実績になる。
3. **判断の場面で計算を呼ぶ**：最適化や追跡は「判断の場面」で呼ばれ、案と根拠を出す。決めるのは人で、承認の記録が残る。
4. **期限を主役にする**：各プロセスの判断期限を集め、「今週・今月決めること」を担当ごとに出す。
5. **実績は次の計画に返す**：工期・費用の上振れ・故障の実績は、次の版の前提を直す（信頼性理論で業界値と混ぜる）。

## 4. workwithai の部品との対応

| 必要なもの | 部品 |
|---|---|
| 入場・見積もり・承認の記録を複数人で共有 | 画面の共有データベース |
| 月次会議の資料を毎月自動で作る | 定期実行 |
| 期限の近い判断、警報、承認依頼を知らせる | 通知（Slack など、送り先は利用者が決める） |
| 見積書・所見報告書（PDF）の取り込み | ファイル保存、文書の取り込み |
| 既存の整備管理システム・状態監視データとの接続 | MCP |
| 資料の下書き、所見の要約 | 画面の中の AI |
