# 工場見積もり比較 × 不確実性下のエンジン入場計画（SAA ＋ モンテカルロ）

[`engine-mro-optimization`](../engine-mro-optimization/) の第2弾です。
第1弾が「いつ・どのワークスコープで」を確定的に決めるのに対し、本サンプルは
**複数工場の見積もりを比較し、費用超過・TAT 遅延・非計画取卸しの不確実性を
モンテカルロで扱って**、次を同時に決めます。

- 各入場予定エンジンの **工場・ワークスコープ・入場月**
- 期間中に長期リースする **予備エンジン台数**

> データは説明用の合成値です。OEM・実在工場の見積もりではありません。

## 入力

### `data/fleet_visits.json` — フリートと入場予定

| キー | 意味 | 実務でのデータ源 |
|---|---|---|
| `installed_positions` / `owned_engines` | 装着位置数 / 保有エンジン数 | 機材計画 |
| `engines[].window` | 取卸し可能期間 [最早, 最遅] 月 | EGT トレンド予測・LLP 残寿命から算出（第1弾の出力でもよい） |
| `engines[].allowed_workscopes` | 状態上許容されるワークスコープ | WSPG、LLP 状況、AD/SB |
| `workscope_build_value` | ワークスコープが生む期間後の搭載寿命価値 | 第1弾モデルの期末価値、社内評価 |
| `short_term_lease` / `long_term_spare` | 短期リース（事後判断）/ 長期リース（事前判断）の単価・上限 | リース会社見積もり |
| `aog_cost_per_month` | 装着位置が埋まらない損失 | 運航収益 |
| `unscheduled_removals` | 非計画取卸し率（1/MTBUR）と所要月数分布 | 自社信頼性データ |

### `data/shop_quotes.json` — 工場見積もりとリスク特性

| キー | 意味 |
|---|---|
| `quotes.{WS}.price / tat` | 見積価格（工数・材料・LLP キット込み）と見積 TAT |
| `slots` | 同時受入枠 |
| `transport_cost` / `transport_months` | 往復輸送・保険・スタンド費 / 輸送による追加の off-wing 期間 |
| `overrun_share` | 分解検査で見つかる不具合（findings）による費用超過のうち、自社負担の割合（T&M = 1、固定価格 = 0、上限付き T&M = 0.5 など） |
| `findings.prob / overrun_mean / overrun_cv` | 不具合による費用超過の発生確率・平均超過率・変動係数（対数正規） |
| `delay.shop_*` | 工場全体の混雑遅延（シナリオ内で同じ工場の全エンジンに共通） |
| `delay.engine_*` | エンジン個別の遅延（部品待ち等） |

見積もりは「確定値」ではなく **価格 ＋ リスク分布** として入れる点がポイントです。
不具合の有無はエンジン側の性質なので、同じシナリオでは全工場に同じ乱数を使います
（共通乱数法）。工場間の差は「請求される確率」と「誰が払うか」に現れます。

## 解き方

```
1. モンテカルロ   N 個のシナリオを生成（費用超過・遅延・非計画取卸し）
2. SAA           二段階確率 MILP を解く
                 1段目: x[e,k,w,t]（工場・WS・入場月）, S（長期予備台数）
                 2段目: シナリオ×月ごとの短期リース l, AOG a（事後対応）
3. EV 計画       全パラメータを平均値にした確定問題を解く（比較用）
4. 評価          独立な大量シナリオ（既定 5,000）で両計画を評価
                 → 平均、P50/P90、CVaR90、AOG 確率、VSS = EV − SAA
5. ギャップ推定   M 回の独立 SAA の下界平均と、評価値（上界）から最適性ギャップを統計推定
```

2段目は「不足分を短期リースで上限まで埋め、残りは AOG」という閉形式になるため、
評価は MILP を解かずに numpy のベクトル演算で行えます。

リスク回避型にしたい場合は `--cvar-weight λ` を指定すると、目的関数が
`E[コスト] + λ·CVaR_α[コスト]` になります。

## 実行

```bash
pip install -r requirements.txt
python run.py                                   # リスク中立 SAA（200 シナリオ）＋ EV 比較
python run.py --replications 5                  # 最適性ギャップの統計推定つき
python run.py --cvar-weight 1.0                 # リスク回避型
python run.py --shops my_quotes.json --json-out plan.json
python -m unittest discover -s tests
```

## 結果例（合成データ、seed=42、評価 5,000 シナリオ、k$）

| 計画 | 平均 | P90 | CVaR90 | AOG 確率 | 長期予備 |
|---|---:|---:|---:|---:|---:|
| EV（期待値計画） | 36,174 | 39,649 | 42,010 | 14.4% | 1 |
| SAA リスク中立 | **35,869** | **38,592** | **40,552** | 7.6% | 1 |
| SAA ＋ CVaR（λ=1） | 37,906 | 39,625 | 40,816 | **1.7%** | 2 |

- 確率計画にした価値（VSS）は **約 305 k$**。平均値だけで計画すると、入場の重なりと遅延の同時発生を過小評価し、AOG 確率が約 2 倍になります。
- リスク中立 SAA は、FULL の1件を **固定価格の OEM 工場** に回しています。見積もりは約 1,000 k$ 高いものの、TAT が安定しているため、入場が重なる時期の欠航リスクを下げられます。
- CVaR 版は、OEM 工場への発注と長期予備を増やす「保険」を買います。AOG 確率は 1.7% まで下がり、ばらつきも小さくなります。一方、サンプル外の CVaR90 はリスク中立版より改善しません。200 シナリオでも裾（最悪 10% ＝ 20 シナリオ）の推定が粗く、過学習するためです。リスク回避を本格的に扱うには、シナリオ数の増加や分解法が必要です。

## 拡張の方向性

- 第1弾（統合計画）の出力を `window` / `allowed_workscopes` / `workscope_build_value` に接続
- 見積もりの更新（分解検査後の確定見積もり）を受けた多段階（ローリング）再最適化
- シナリオ数を増やすための L-shaped 法（Benders 分解）
- 工場の枠を不確実に（他社の入場による混雑）、輸送リードタイムの分布化
