# 工場見積もり比較 × 不確実性下のエンジン入場計画（SAA ＋ モンテカルロ）

[`engine-mro-optimization`](../engine-mro-optimization/) の第2弾です。
第1弾が「いつ・どのワークスコープで」を確定的に決めるのに対し、本サンプルは
**複数工場の見積もりを比較し、費用超過・TAT 遅延・非計画取卸しの不確実性を
モンテカルロで扱って**、次を同時に決めます。

- 各入場予定エンジンの **工場・ワークスコープ・入場月**
- 期間中に長期リースする **予備エンジン台数**

> データは説明用の合成値です。OEM・実在工場の見積もりではありません。

## 入力

### `data/fleet_visits.json` — フリートと入場予定

| キー | 意味 | 実務でのデータ源 |
|---|---|---|
| `required_positions` | 月ごとの必要装着数（＝2 ×便を飛ばすのに要る機数）。**飛ばし続ける基数** | 便の計画（季節指数）、機体重整備の計画 |
| `buffer_spares` | 月ごとに棚に置いておく使用可能な予備エンジン数。**バッファ** | 非計画取卸し率 × 戻るまでの期間 → ポアソン 95% 点 |
| `owned_engines` | 保有エンジン数（グループ内で融通） | 機材計画 |
| `engines[].hazard` / `watch` / `operator` | 取卸し可能になってからの月あたり故障確率、要監視フラグ、運航会社。**ヤバいやつを弾く** | EGT トレンド、ボアスコープ所見、信頼性データ |
| `engines[].window` | 取卸し可能期間 [最早, 最遅] 月 | EGT トレンド予測・LLP 残寿命から算出（第1弾の出力でもよい） |
| `engines[].allowed_workscopes` | 状態上許容されるワークスコープ | WSPG、LLP 状況、AD/SB |
| `workscope_build_value` | ワークスコープが生む期間後の搭載寿命価値 | 第1弾モデルの期末価値、社内評価 |
| `short_term_lease` / `long_term_spare` | 短期リース（事後判断）/ 長期リース（事前判断）の単価・上限 | リース会社見積もり |
| `aog_tiers` | 装着位置が埋まらないときの欠航コスト。利益率の低い便から順に欠航させる段階制 | 路線別の貢献利益 |
| `aircraft_substitution` | 別機種で代替運航する費用と、他機種が回せる月別の能力 | 機材計画、運航コスト |
| `unscheduled_removals` | 非計画取卸し率（1/MTBUR）、所要月数分布、在翼故障時の費用倍率と追加月数 | 自社信頼性データ |
| `start` | 計画開始の暦月（例 `2026-10`）。年度・繁忙期の判定に使う | — |
| `green_time_value_per_month` | 取卸し期限前に外すことで捨てる搭載寿命 1 か月の価値 | 整備費 ÷ 搭載期間、リース料相当 |
| `aog_peak_multiplier` / `short_term_lease.max_engines_peak` | 繁忙期（暦月）の欠航コスト倍率と、繁忙期に借りられるリース台数 | 運航計画、リース市況 |
| `llp_kits` | LLP キットを使うワークスコープ、調達リードタイム、手持ち数、緊急調達の割増 | 調達部門・OEM 納期 |
| `service_target.max_aog_prob` | 欠航確率の目標（要望として課すとき） | 運航部門 |
| `budget` | 年度開始月と年度別の整備予算（入場月の年度で期待費用を計上） | 予算計画 |
| `fx.volatility` | 外貨建て見積もりの為替変動（計画期間の対数正規σ） | 為替オプションのインプライド・ボラティリティ等 |

### `data/shop_quotes.json` — 工場見積もりとリスク特性

| キー | 意味 |
|---|---|
| `quotes.{WS}.price / tat` | 見積価格（工数・材料・LLP キット込み）と見積 TAT |
| `slots` | 同時受入枠 |
| `transport_cost` / `transport_months` | 往復輸送・保険・スタンド費 / 輸送による追加の off-wing 期間 |
| `overrun_share` | 分解検査で見つかる不具合（findings）による費用超過のうち、自社負担の割合（T&M = 1、固定価格 = 0、上限付き T&M = 0.5 など） |
| `findings.prob / overrun_mean / overrun_cv` | 不具合による費用超過の発生確率・平均超過率・変動係数（対数正規） |
| `delay.shop_*` | 工場全体の混雑遅延（シナリオ内で同じ工場の全エンジンに共通） |
| `delay.engine_*` | エンジン個別の遅延（部品待ち等） |
| `currency` | 見積通貨。`HOME` 以外は為替リスクを負う |
| `booking_lead_months` | 枠予約のリードタイム（判断期限の計算に使う） |
| `expedite.fee / tat_reduction` | 特急対応の料金と TAT 短縮月数 |
| `volume_commitment.min_visits / shortfall_penalty` | 契約上の最低発注件数（テイク・オア・ペイ）と不足1件あたりの違約金 |
| `max_visits` | 受け入れ上限（中古市場のエンジン在庫など） |

見積もりは「確定値」ではなく **価格 ＋ リスク分布** として入れる点がポイントです。
不具合の有無はエンジン側の性質なので、同じシナリオでは全工場に同じ乱数を使います
（共通乱数法）。工場間の差は「請求される確率」と「誰が払うか」に現れます。

## 解き方

```
1. モンテカルロ   N 個のシナリオを生成（費用超過・遅延・非計画取卸し）
2. SAA           二段階確率 MILP を解く
                 1段目: x[e,k,w,t]（工場・WS・入場月）, S（長期予備台数）
                 2段目: シナリオ×月ごとの短期リース l, AOG a（事後対応）
3. EV 計画       全パラメータを平均値にした確定問題を解く（比較用）
4. 評価          独立な大量シナリオ（既定 5,000）で両計画を評価
                 → 平均、P50/P90、CVaR90、AOG 確率、VSS = EV − SAA
5. ギャップ推定   M 回の独立 SAA の下界平均と、評価値（上界）から最適性ギャップを統計推定
```

2段目は「不足分を短期リース → 別機種での代替運航 → 利益率の低い便からの欠航、の順に安いものから埋める」という閉形式になるため、
評価は MILP を解かずに numpy のベクトル演算で行えます。

リスク回避型にしたい場合は `--cvar-weight λ` を指定すると、目的関数が
`E[総コスト] + λ·CVaR_α[総コスト]` になります（1段目の長期予備費・整備価値も含めた総コストの CVaR）。

## 実行

```bash
pip install -r requirements.txt
python run.py                                   # リスク中立 SAA（200 シナリオ）＋ EV 比較
python run.py --replications 5                  # 最適性ギャップの統計推定つき
python run.py --cvar-weight 1.0                 # リスク回避型
python run.py --shops my_quotes.json --json-out plan.json
python -m unittest discover -s tests
```

## 急ぐべきか（判断期限）

計画を選ぶ前に、実務でまず問われるのは **「今、決めなければならないエンジンはどれか」** です。
`shop_mc/urgency.py` は計画中の各エンジンについて次を出します。

- **判断期限** = 計画上の入場月 − 最も長いリードタイム（工場の枠予約、手持ちで足りない LLP キットの発注）
- **入場月ごとの期待総コスト曲線**：そのエンジンだけを動かし、工場・ワークスコープ・特急を選び直したときの値。会社の制約（予算・LLP キット・工場枠）で入れない月は、どの制約に阻まれたかも記録
- **急いだ場合 / 限界まで待った場合** のコスト差

## サンプルの規模

大手航空会社の1型式を想定しています（`data/generate_fleet.py` に推定根拠）。

| 項目 | 値 | 根拠 |
|---|---:|---|
| 機数 | 62 機（737-800） | JAL 本体の 737-800 在籍数（Wikipedia "Japan Airlines fleet"、2026年3月） |
| 装着位置 / 保有エンジン | 124 / 136 基 | 予備比率 約 9% |
| 2 年間の入場予定 | 44 件 | CFM56-7B の成熟期ラン 1.0〜1.5 万サイクル、年約 2,000 サイクル → 5〜7 年に 1 回 |
| 整備費 | PR 約 250 万ドル、LLP 一式込みで 590〜990 万ドル | 公開ベンチマーク（重整備 210〜280 万ドル、LLP 一式 250〜600 万ドル） |

JAL 本体の全型式（183 機・装着 366 基・保有 約 400 基・2 年で約 140 件）に広げる場合は、型式ごとの問題を全社予算・工場枠で結合する分解法が必要になります（今後の拡張）。

## 結果例（合成データ、seed=42、評価 5,000 シナリオ、k$）

| 計画 | 平均 | P90 | CVaR90 | 欠航確率 | 今決める | 求解 |
|---|---:|---:|---:|---:|---:|---|
| 見積もりどおり（確定） | 146,477 | 171,978 | 182,809 | 77.9% | 1 基 | 最適 |
| 期待値（EV、確定） | 140,596 | 164,927 | 174,704 | 36.5% | 1 基 | 最適 |
| 悲観値 P90（確定） | — | — | — | — | — | 実行不能 |
| SAA リスク中立 | **139,174** | 161,954 | 170,512 | 13.1% | 1 基 | 時間切れ |
| SAA ＋ CVaR λ=0.3 | 139,787 | 160,594 | 168,806 | 9.1% | 0 基 | 時間切れ |
| SAA ＋ CVaR λ=1 | 140,623 | **159,485** | **166,514** | **6.9%** | 0 基 | 時間切れ |
| SAA ＋ CVaR λ=3 | 142,182 | 160,300 | 167,209 | 6.8% | 0 基 | 時間切れ |

- 124 装着位置の規模では、見積もりを額面どおりに信じると欠航確率は 8 割近く、期待値計画でも 4 割弱になります。確率計画では 13%、CVaR を加えると 7% 前後まで下がります。
- 悲観値（全コストを P90）で見ると、年度予算・LLP キット・工場枠をすべて満たす計画が存在しません。
- 確率計画 4 本は 240 秒の時間制限で打ち切った暫定解です（`--time-limit` で延長可）。λ=3 が λ=1 より平均・P90 とも悪いのは打ち切りの影響で、最適性は保証されていません。
- 結果は前提（予備比率、繁忙期リース枠、予算水準など）に強く依存します。実データで較正してから使ってください。

## 年間基準（合意値）と、ユースケース別の増減（`baseline.py`）

年間の「暗黙の合意」を基準として固定し、ほかのユースケースの問いはすべて **基準からの増減** で答えます。

```bash
python lifecycle.py --fleet-out data/fleet_visits_lifecycle.json   # 20 年シミュレーションから現在の機材状態を作る
python baseline.py freeze  --out baselines/2026-10.json            # ① 年間基準を版つきで固定（入力の指紋つき）
python baseline.py compare --baseline baselines/2026-10.json --md-out deltas.md   # ②〜⑤ を並列に解き、増減表を出す
```

| ユースケース | 問いの例 | 増減で見るもの |
|---|---|---|
| ① 年間基準計画 | 来年度は何件・いくらか | これが基準（定常値：年 28.7 件・1.85 億ドル、2 年の計画：45 件） |
| ② 月次の入場判断 | 工場の TAT が延びたら、今月の判断は変わるか | 件数・年度別支出の移動、前倒し月数 |
| ③ 工場・契約 | 固定価格化、枠の確保、プール契約 | 総コスト、欠航確率、工場の配分 |
| ④ 資産戦略 | 中寿命エンジン、予備追加、部品取り、機材更新 | 入場件数、年度別支出、保有基数 |
| ⑤ リスク対応 | LLP 逼迫、複合ストレス | 追加コスト、欠航確率、前倒し |

基準を固定した後に入力データが変わると、`compare` がその旨を警告します（比較の前提がずれるため）。

## 意思決定レポート（`decide.py`）と分析

要望は同時にすべては満たせないため、優先順位に沿って結論を出すレポートを生成します。

```bash
python levers.py        # よく取られる打ち手を 1 つずつ加えた効果 → levers.json
python explore.py       # 確定できないパラメーター 5 つ × 108 通りで打ち手を最適化に選ばせ、決定木で分類 → explore.json
python sensitivity.py   # 中寿命エンジン価格の損益分岐と、予備の厚さ × 他機種の肩代わりの関係 → sensitivity.json
python decide.py        # 上 3 つを読み込み、前提 4 ケース × 要望 × 代替案 4 つを並列に解いて report.html を出力
```

- **要望の優先順位**（既定、`requirement_priority` で変更可）：欠航確率目標 → 予備バッファ → 契約の最低発注量 → 年度予算 → LLP キットは手持ち → 予備を増やさない。耐空性（期限・要監視エンジン）はその上で、緩めません。全要望が満たせないケースでは、下位から 1 つずつ緩めて成立するところを示します。代替案の推奨は、上位の要望を満たすものを優先（辞書式）し、同順位ならコストで選びます。
- **前提ケース**：基準／MRO 混雑（外部工場 TAT +1 か月）／LLP 逼迫（手持ち半減・調達 12 か月）／複合ストレス。
- **レポートの中身**：結論（推奨・今決めること・承認事項）、あるべき姿（月別の必要装着数＋バッファと使えるエンジン数）、要望の衝突と値段、代替案×ケースの相互評価、判断期限、期限前取卸しの例外理由、打ち手の効果、条件別の答え、見直しのトリガー。

### 分析から分かったこと（合成データ）

- 判断を最も大きく分けるのは **中寿命エンジンの正味価格**：5,500 k$ 以下なら入場の 3 分の 1 以上を中古エンジンとの入れ替えにするのが得、6,500 k$ 以上なら工場整備のみ。市場見積もりの取得が最優先。
- **LLP 逼迫**のときは、下位の要望（予備を増やさない、キットは手持ち）を諦めれば残りは守れる。
- **機材割当**（どの機体をどの便に使うか）は別の最適化問題。エンジン計画との接点で効くのは「他機種が月に何機肩代わりできるか」で、1 機の価値の設定はほぼ計画を変えない。予備が薄い（156 基）と、代替なしの欠航確率 最大 51% が代替ありで 6% に下がる。
- 予備エンジンの追加は、どの条件でも最適化に選ばれなかった（プール契約や代替運航のほうが安く欠航リスクを下げる）。

## 解き方を並列に比較して選ぶ（`compare.py`）

```bash
python compare.py                  # 7 手法をプロセス並列で解き、compare.json と compare.html を出力
python compare.py --workers 8
```

上表の7つの解き方をプロセス並列で解き、同じ評価シナリオで評価し、各計画の判断期限分析も並列で行います（サンプルでは 4 ワーカーで数十秒）。
生成される `compare.html` は外部依存のない1ファイルの選択画面で、次を表示します。

- 冒頭に「急ぐべきか」：今月決めるべきエンジン数、判断期限、急いだ／待った場合のコスト、入場月ごとのコスト曲線
- 「コストを抑える ↔ 欠航を避ける」スライダー。パレート最適な計画の中から、指定した重みに最も合うものを推奨します（平均コストと欠航確率を候補内で正規化して重み付け）
- コスト × 欠航確率の散布図とパレートフロント
- 選択中の計画の総コスト分布（期待値計画との比較）と入場スケジュール（工場別の色、P90 までの幅）
- 会社の制約の充足状況（年度予算の消化率、LLP キット、最低発注量、早期取卸しで捨てる寿命、特急件数）
- 前提にした不確実性の分布（工場別の見積もり超過・TAT 遅延、為替、非計画取卸し件数、欠航コストの季節変動）
- 全手法の比較表（実行不能だった解き方も表示）

WorkWithAI SDK では、この HTML をエージェントのセッション内で生成し、計画担当者の画面に表示する使い方を想定しています。

## 拡張の方向性

- 第1弾（統合計画）の出力を `window` / `allowed_workscopes` / `workscope_build_value` に接続
- 見積もりの更新（分解検査後の確定見積もり）を受けた多段階（ローリング）再最適化
- シナリオ数を増やすための L-shaped 法（Benders 分解）
- 工場の枠を不確実に（他社の入場による混雑）、輸送リードタイムの分布化
