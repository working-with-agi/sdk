# 批判：story_エンジンから空港まで.md

（会社 A の JSON は `fleet/capacity_*.json` のように書く。規則層の指摘は L9・L35・L37 の言い切り 3 件。L37 はすでに弱めてあり問題は小さい）

## 総評
- いちばん強い主張：キャップのまま需要が伸びると、失う売上は 5 年で約 2 倍（L10、L45–46）。出力（`capacity_*.json` の `years[].capped`）と一致し、感度（286〜411 億円）も示してある。
- いちばん弱い根拠：「枠の価値の大半は他社から移る取り分」（L12、L104）。これはモデルを組んだときの置き方（路線の総需要は便数で増えず、便数の比率で分ける）から自動的に出る形で、計算で見つかった事実ではない。7〜8 章の政策の結論はこの一点に乗っている。
- 全体の確からしさ：1〜6 章の数字はほぼ出力と合う。7〜8 章は FY2027・FY2030・FY2032 の値を、年度と弾力性を書かずに一つの表に混ぜている。経営・政策への言い方は、数字が支える範囲より一段強い。

## 言い過ぎ
1. L11・L94「羽田だけ広げても、対向空港（伊丹・新千歳・福岡）が受けられなければ価値の半分も出ない」「対向空港と組でないと半分も出ない」
   → 羽田 +20 往復の場合、FY2030 では羽田だけで +122.5、上限なしで +204.8 なので、約 6 割は出る（`investment_*.json` の `rows[hnd20].gain_oku_per_year` と `rows[hnd20_open]`）。FY2027 でも +93.8／+159.2 で約 6 割。「半分に届かない」が成り立つのは +30 往復より上だけ（FY2027 の +30 で 93.8／219.0）。
   → 直し案：「羽田 +20 往復なら、対向空港がそのままでは価値の約 4 割が出ない。+30 往復より先では半分も出ない」
2. L104「その全部が便数の取り分が増えて他社から移った旅客で…一社に枠を配ることは、旅客を会社の間で移すことに近い」
   → `investment_*.json` の `assumptions.split` 自身が「他社の便と乗れない旅客はモデルの外なので、…社会の側の増分は分けられない」と書いている。他社も同じ羽田のキャップの下で旅客を乗せられずにいれば、移った需要の一部は他社が運べなかった旅客で、市場全体では新しく運べた分になる。「全部が移し替え」は測った結果ではなく、置き方から出てくる形。
   → 直し案：「このモデルでは路線の総需要を便数で増やさず、便数の比率で分けているので、増えた旅客は形の上ではすべて他社の取り分から来る。そのうち他社が乗せられなかった旅客がどれだけ含まれるか（市場全体で新しく運べた分）は、まだ分けられない」
3. L102「運賃で今の枠の価値を取り切り」
   → 一社だけで動く場合の弾力性（−1.4）では、運賃の効果は +13〜21 億円（`fares_*.json` の `rows`、FY2027・FY2030）。失う売上（167〜258 億円）の 1 割前後で、「取り切る」とは言えない。+124〜149 億円は市場全体が一緒に動く場合で、本文（L81）も「確からしさは低い」と書いている。
   → 直し案：「他社が運賃を据え置くなら、運賃で取り戻せるのは年 13〜21 億円で、取り逃しの一部にとどまる」
4. L13・L111「運賃を上げれば 737・767 のエンジンが傷む」
   → 成り立つのは FY2027・弾力性 −0.8 の場合だけ（737 の整備費 263.2 → 265.5、767 の稼働倍率 1.122 → 1.182）。−1.4 では運賃はほとんど上がらず（新千歳・那覇は下がる）、767 の稼働倍率は 1.122 → 1.093 と下がる。FY2030 は −0.8〜−1.4 のどれでも 737 の整備費は 262.8〜262.9 で動かない（`fares_*.json` の `rows[].engines`）。
   → 直し案：「運賃を大きく上げられる場合（市場全体が一緒に動く場合）に限り、旅客が減って小さい機体に移るので、737・767 の整備費が年 2〜5 億円増える。一社だけで動く場合はほとんど動かない」
5. L35・L83「737 を借りても、入れる枠がない」「リース：使わない」
   → 結果の文書 4 章（L88）は、リース料（1 機・月 850 k$）が no_source の仮定で、安く借りられれば売上のために借りる解も出うると書いている。ストーリーではこの条件が落ちている。
   → 直し案：「今のリース料の仮定（no_source）では借りる解は出ない。もっと安く借りられれば変わりうる」

## 根拠の弱い数字
1. 「1 往復で年 約 8〜13 億円」（L12・L84・L92・L102）
   → FY2027 の再配分シナリオで、枠を得る側の 7.7〜8.9 と失う側の 10.6〜12.7 をつないだ幅（結果の文書 4 章、会社 A の `fleet/*.json` の `trunk.slot_scenarios`）。申請する側（得る側）に効くのは約 8〜9 億円。FY2030 の投資シナリオでは 9.6〜10.6（`investment_*.json` の `gain_per_added_round_trip_oku`）。
   → 得る側と失う側、年度を分けて書く：「枠を得る側は 1 往復あたり年約 8〜9 億円（FY2027）、需要が伸びた FY2030 では約 10 億円。失う側は約 11〜13 億円」
2. 7 章の経営の表（L81–84）
   → +13 は FY2027・−1.4、+150（149.4）は FY2030・−0.8。「−26〜−83」は −25.8 が FY2030・A350 +2、−82.6 が FY2027・A350 +4。「+2〜5 億円」は FY2027・−0.8 だけ。年度も前提も違う値が一つの幅にまとめてある。
   → 列に「年度」「前提（弾力性・羽田の枠）」を足し、範囲の両端に年度と前提を添える。
3. 7 章の政策の表（L90–96）
   → 「値段」の列に、ほぼ 0／小さい／1 往復あたり 34 億円（単価）／846〜996 億円（会社 A が使う容量の費用の総額）／（参考）事業費 6,700 億円・5,950 億円、と違う物差しが並ぶ。「効果（会社 A の側、年）」の列には、1 往復あたりの億円（FY2027）、総額の億円（+123・+196、FY2030）、さらに他空港の国際線の発着回数（3.9 万回、会社 A の効果ではない）が混じる。年度の注記はない。
   → 「値段」を「事業費の総額」と「会社 A が使う容量ぶん」の 2 列に分け、効果は FY2030 の差し引きの増分にそろえる。先例の行は効果の列から外して注に回す。
4. 5 章「FY2032 には +12 往復、差し引きは +150 億円」（L56）
   → この値は対向空港の上限を入れていない（`capacity_*.json` の `years[FY2032].follow.dest_caps = false`）。路線ごとに見ると新千歳 +4・福岡 +3 で、6 章の余地（新千歳 3・福岡 2、no_source）を超える。6 章で「合計 12 往復」と置いているのに、5 章の +12 往復がそのまま飛べるかどうかは書かれていない。
   → 「対向空港の上限を入れない場合」と明記し、上限を入れた値を並べる（同じ +12 往復でも、FY2030 の `hnd12` は使えない枠が 2 往復ある）。
5. 「幹線に回せる 737 は月に 13〜21 機あるのに、使うのは 6〜12 機」（L33）
   → 会社 A の `fleet/*.json` の `trunk.rows[]` では、FY2027 の `available.737` は 13.9〜21.2 で合う。一方 `used_p50.737` は 5〜7、`used_p90` も 5〜7 で、「12」は出力にない。近い値は運賃を −0.8 で大きく上げたときの 10.8（`fares_*.json`）だけ。
   → 「使うのは 5〜7 機（p50）」に直すか、12 の出どころを書く。

## 抜けている別の説明・反論
1. 「大半が他社からの取り分」は置き方そのもの：路線の総需要を便数で増やさず、取り分を便数の比率で決める置き方では、便を足すと需要は必ず他社から来る。便が増えると需要そのものが増える効果（新しい需要）が入っていないので、「移し替えに近い」は前提の言い換えになっている。結果の文書 5.7（L246）も、取り分を据え置いた比べ方はこのモデルではできないと書いている。
2. 運賃を上げる手と枠を申請する手はぶつかる：運賃を上げると運ぶ旅客は 12 万〜243 万人減る（FY2027）。結果の文書 5.4（L174）は、羽田の枠は公共の資源で、旅客を減らすことは再配分の評価（利用者の利便）に響くと書いているが、8 章の経営への助言（運賃で取り切り、再配分で 1 往復の価値を示す）はこの緊張に触れていない。
3. 失う売上は「取り逃しの目安」で、多めにも少なめにも出る：結果の文書 5.1（L105）は二つの偏りが逆向きに効くと書いている。ストーリーの L10・L52 は「失う売上」「取り逃しが積み上がる」と言い切っており、振り替えを入れていない分（多めに出る側）が 9 章にしか出てこない。
4. 縛りは工場に移りうる：9 章（L118）に一文あるが、8 章の「手ごとに整備費と入場の前倒しを並べた表を作った」（L111）は、工場の空き・予備エンジンを入れていない表である。767 は計画の上限 ×1.10 に当たっている（`capacity_*.json` の `engines[767].at_util_cap = true`）ので、767 に寄せる手（L56–58）はまず工場と退役計画で詰まる可能性がある。
5. 運用の見直しの先例（L93）の当てはまり：羽田の経路の見直しで増えたのは国際線で、会社 A の国内幹線に同じ手が効くかは示されていない。「値段：小さい」は騒音・地元の合意の費用を入れていない。

## 読み手ごとの引っかかり
- 査読者：「他社からの取り分」と「対向空港の余地 12 往復」は、どちらも置き方（取り分＝便数の比率、余地は no_source）で決まる。ここを変えたときの感度がない。
- 経営者：経営の手の表は、範囲の両端の年度と前提が違うので、手どうしの比較に使えない。一社で動く前提にそろえた一列（運賃 +13〜21、大型機 −26〜−83、申請 約 8〜10）がほしい。
- 整備計画の担当者：767 は稼働倍率がすでに上限 1.10 に当たっているのに、「整備は 767 に寄る」の後に、工場・予備エンジン・退役の数字がない。「運賃で 737・767 が傷む」は一つの前提の場合だけ。
- 反対論者：便を増やすと需要も増える路線なら、増えた旅客は他社からではなく新しい需要かもしれない。乗れない旅客が増えたのも、便を割り振る置き方の結果かもしれない。
- 初めての読者：p50、稼働倍率、前倒し（基）、差し引き、no_source、往復（1 日）が説明なしに出る。7〜8 章の「億円」が年なのか総額なのか、どの年度なのかが表ごとに違う。

## 直す順番
1. 7 章の二つの表に「年度・前提」の列を足し、値段（総額／会社 A が使う容量ぶん）と効果（FY2030 の差し引きの増分）の単位をそろえる。
2. L12・L104 の「他社から移る取り分」を、置き方から出る形であること、他社が乗せられなかった旅客を分けられないことと一緒に書き直す。
3. L11・L94 の「半分も出ない」を、+20 往復では約 6 割出る、+30 往復より先で半分を切る、に直す。
4. 「8〜13 億円」を得る側（約 8〜9、FY2030 は約 10）と失う側に分ける。L102 の「取り切り」を弱め、運賃を上げる手と再配分の評価（利用者の利便）のぶつかりを 8 章に足す。
5. L13・L81 の「運賃で 737・767 が傷む」を条件つき（市場全体が動く場合、FY2027）にし、L33 の「6〜12 機」と L56 の「+12 往復・+150 億円（対向空港の上限なし）」を出力に合わせる。
