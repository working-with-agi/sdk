# 批判：handover/04_docs/fleet_from_demand_結果.md

## 総評
- いちばん強い主張：羽田の枠のキャップの下では、需要が伸びても運べる旅客は座席を埋める分しか増えず、737 のエンジン入場は 6〜7 基の前倒しで止まる（L95, L106）。数字は fleet/capacity_jal.json と合う（規則層が見つけられなかった L128・L130・L132 の 159.2・296.1・346.9 は、`expansion[].hub_only.margin_oku` の 1222.7・1359.6・1535.0 から基準の 1063.5・1188.1 を引いた差で、計算は合っている）。
- いちばん弱い根拠：5.4〜5.5 節の運賃の結論。採る弾力性（−0.8／−1.1／−1.4）は自社の推定（L172〜176）では絞り込めず、日本を含む「アジア域内」の一般値に頼っている。伊丹から上げるという結論も、路線ごとに同じ弾力性を置いた結果。
- 全体の確からしさ：機材とエンジンの数え方は出力と合っていて、仮定もかなり書けている。ただ「縛りは枠」「借りる理由は枠」は、他社の便数と配分を据え置いた設定からほぼ決まる結論。そこが観測から出た事実のように書かれている。

## 言い過ぎ
1. L64「縛りは機体の数ではなく羽田の枠。」→ 他社の便数を据え置き、自社の幹線便数を枠から決めているので、枠が縛りになるのはモデルの設定から出る（L68, capacity_jal.json `assumptions.years`）。→ 直し案：「他社の便数と枠の配分を据え置くこのモデルでは、縛りは機体の数より羽田の枠になる。」
2. L81「借りる解が出るのは…ときだけ。そのとき借りる理由は売上ではなく、枠を使い続けること」→ 枠を使う下限 98% を制約として入れた結果（fares_jal.json `assumptions.frequencies`）。リース料が no_source（L189）なので、条件が変われば売上目的のリースも解に出る。→ 直し案：「このモデルの範囲では、借りる解は 737 が足りず欠航するときにだけ出た。理由は枠を使う下限（98%）を守るためで、リース料の仮定しだいで変わりうる。」
3. L152「最初に上げるのは伊丹…上げ幅は月の繁閑よりも路線で決まる。」→ 路線ごとに同じ弾力性を置いている（L183 で区別していないと自分で書いている）。伊丹は新幹線との競合が強いので、弾力性が大きければ順番は変わりうる。→ 直し案：「弾力性を全路線で同じとすると、最初に上げるのは伊丹になる。新幹線との競合を入れると順番が変わる可能性がある。」
4. L179「幹線の旅客は運賃より座席の供給で決まっている。」→ 座席の弾力性 0.70（L175）は、需要が伸びる路線に会社が座席を足すという逆の因果でも同じ値が出る。運賃の操作変数が弱い（偏決定係数 0.01、L178）以上、座席についても因果は言えない。→ 直し案：「旅客は座席と強く連動する（0.7）。座席の供給が旅客を決めるのか、需要に合わせて座席が置かれるのかは、この推定では分けられない。」
5. L155「運賃は枠の代わりにはならない」→ 比べている「羽田 +20 往復だけで +204.8 億円」は対向空港の上限を入れない値（fares_jal.json `fares_vs_slots.slots_today_fares.margin_oku` = 204.8、capacity_jal.json の FY2030 +20 `hub_only`）。上限を入れると +122.5（L131）。→ 直し案：「羽田 +20 往復だけで +204.8 億円（対向空港の上限を入れると +122.5 億円）。」と並べ、そのうえで比べる。

## 根拠の弱い数字
1. L79「失う側は 1 往復あたり年に 11〜13 億円、得る側は 8〜9 億円」→ 表 L72〜77 から割ると −9 で 10.6、−3 で 12.7、+3 で 7.7、+5 で 8.9。書いてある幅が表と少しずれている。→ 割り算を表に列として足し、幅は「約 10.6〜12.7／7.7〜8.9」と表の値から書く。
2. L144・L151「−0.8 なら +20〜45%」「差し引き +124.2 億円」→ 運賃 1.45 倍（伊丹）で旅客 −243 万人（基準 11,351 千人の約 2 割）。直線の需要曲線（no_source、fares_jal.json `assumptions.demand`）を今の運賃から大きく外れた所まで伸ばしている。→ 弾力性の幅（L182 の −0.5〜−0.85）の両端でも解き、運賃 1.2 倍以上の解には「直線を外挿した域」と印をつける。
3. L120「損益が合うのは 1 機・月 約 320 k$ 以下」→ 足す A350 の費用 1,100 k$（no_source、capacity_scenarios.py `WIDEBODY_K_PER_AIRCRAFT_MONTH`）と、FY2030・+4 機の一点（(42.2−18.4)÷4）から逆算した値。→ 何機足すかで 1 機あたりの稼ぎは変わる（+2 機なら (25.6−10.1)÷2 ≈ 7.8 億円）。+2・+4 の両方で損益分岐を書く。
4. L50「767 の稼働倍率 1.10（上限）」と L102「767 1.122」→ 同じ FY2027・p50 で値が違う。capacity_jal.json の `assumptions.engines` は「計画の上限 ×1.10 で切らない」と書いていて、定義が違う。→ 3 節は上限で切った値、5 節は切らない値だと注を足す。
5. L29・L91〜93 需要の伸び（年 3.8%）、為替 157 円/$（L3）→ 5 年後の失う売上 344.1 億円や差し引きは、この二つに直接依存する。文書の中に出典も感度もない。→ 出典か no_source を書き、伸び率を ±1 ポイント動かした FY2032 の行を一つ足す。

## 抜けている別の説明・反論
1. 新千歳・那覇の搭乗率が実績より低い（L62）原因を「A350 は幹線以外に行き先がない」と見ているが、検証されていない。ばらつきの仮定（L196）、または 2024 年の全社の座席利用率と路線の値の差でも説明できる。「会社 B はこの調整をしていない」の「調整」の中身も書かれていない。
2. 失う売上 166.8〜344.1 億円（L88〜93）は「取り逃した機会の上限」と L97 にあるが、L190 は「見送りの売上は下限」と書いている。振り替えを入れていない点（下限の側）と、運賃を固定している点（上限の側）が逆向きに効く。どちらが勝つかを書かないと、読み手は数字の向きを決められない。
3. 運賃の結論は、他社の運賃が反応しないこと（L156）と、便数の取り分が変わらないことを置いている。他社が追随しない場合の路線の弾力性 −1.4 を使えば、上げる価値は小さい（FY2027 +13.1 億円）。結論は「他社がどう反応するか」でほぼ決まる、と前に出すべき。
4. 文献の確認の状態が文書と出力で食い違う。L162 は InterVISTAS を「確認」としているが、fleet/fares_jal.json `assumptions.demand` は「原典は未照合」のまま（data/elasticity/literature.json は `checked: true`）。出力の注が古いのか、確認が後から行われたのかを揃えないと、査読者はどちらも信用しにくい。
5. エンジンの前倒し（737 7 基、767 17 基、L49〜50）を数えているが、工場の受け入れ能力、予備エンジン、部品の制約が出てこない。前倒しが入場の集中を起こすなら、縛りは枠ではなく工場の側に移るかもしれない。

## 読み手ごとの引っかかり
- 査読者：結論の大半（枠が縛り、伊丹から値上げ、借りる理由）は、他社の便数を据え置くことと全路線で同じ弾力性を置くことに依存する。感度は弾力性の 3 点だけで、伸び率・為替・ばらつきの感度がない。
- 経営者：「何をするか」が 5.3 節の「対向空港の容量が増えないと出てこない」と 5.4 節の運賃に分かれていて、次の打ち手の順番が書かれていない。数字は点の値ばかりで、p10／p90 の幅がない（L66 以降はすべて p50）。
- 整備計画の担当者：767 の前倒し 17 基（L50）、+45 往復で 737 19 基（L137）を工場が受けられるかが書かれていない。稼働倍率 1.10 と 1.122 の定義の違い（L50／L102）でつまずく。
- 反対論者：搭乗率が実績より低い路線、座席の弾力性 0.7、伊丹の値上げ余地は、どれも「需要の質（ビジネス／レジャー）」と「新幹線との競合」で別に説明できる。この二つはモデルの外だと L183 が認めている。
- 初めての読者：「年次の版」「稼働倍率」「入場の前倒し」「p50／p90」「座席キロ」に説明がない。L24〜25 の表は行ごとに年度が混ざっていて読みにくい（FY2027 の機数と FY2028 の足りない月）。

## 直す順番
1. L155 の運賃と枠の比較に、対向空港の上限を入れた +122.5 億円を並べる。
2. L64・L81 の「縛りは枠」「借りる理由」を、据え置きの設定から出る結論として書き直す。
3. L152・L179 の言い切りを弱め、同じ弾力性・逆の因果・新幹線の別の説明を一文ずつ足す。
4. fares_jal.json の「原典は未照合」と L162 の「確認」を揃える。767 の稼働倍率 1.10／1.122 の定義に注をつける。
5. 伸び率・為替・需要のばらつきの感度（一行ずつ）と、5.3 節の差（159.2 など）の計算式（hub_only の差し引き − 基準）を足す。
