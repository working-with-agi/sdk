## SDK の改善点（例を作る中で見つかったもの）

| # | 改善点 | 影響 |
|---|---|---|
| S1 | SDK の入口が常に xterm を読み込むため、Node のスクリプトからそのまま使えない。Node 用の入口が必要 | サーバー側・定期実行からの利用 |
| S2 | セッションの出力やファイルを REST で読めない。追加の指示（フォローアップ）も送れない | 結果の取り込み、会話の継続 |
| S3 | `addPane` に `prompt` がなく、2 つ目のペイン（検証担当など）に指示を渡せない | 複数エージェントの役割分担 |
| S4 | `WorkAGI` に `KnowledgeClient` を作る入口がない | 一貫した使い勝手 |
| S5 | セッションや文書にメタデータを付けられない（ラベルと ID で区別するしかない） | 版管理、基準との対応付け |
| S6 | 同期コネクタの設定キー、`schedule` の時間帯、`prompt` の渡され方、既存 ID でのアップロードの上書き挙動が文書化されていない | 実運用の前提 |
